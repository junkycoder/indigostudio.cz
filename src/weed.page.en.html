Web Editor

Web Editor is a browser in which you point at an element of your website and say what should change. Out of that it assembles a precise request for your own agent — with the selector, the styles, the element's surroundings and the system the site runs on.

The context is read from the rendered page, not from your source code. You don't have to describe which element you mean, or find where it lives in the code. There is one goal: that the agent gets it right the first time and doesn't have to ask. Your sentence is never translated — it goes out exactly as you said it. Web Editor adds a description of what it sees on the page and the agent does not; the decision about what should happen stays with you and with it. Anything it cannot evidence from the page is left out: an uncertain layer costs the agent an extra round.

You share a finished request straight from the app into your agent's app, or send it to the remote MCP: then one address is all the agent needs — it reads the requests itself and ticks off the ones it has done. The clipboard and the zip always work, need no consent and no us — and that is the way out of the browser extension.

Verify it in the code; it is a description of what is visible.

How it goes

  1. Open your website in Web Editor on your phone, or browse it in Chromium with the extension.
  2. Select an element with the crosshair and type or dictate what should change.
  3. Add the request to the list. How many there are before you hand the list over is up to you.
  4. Hand it to your agent — clipboard, zip, share sheet on the phone, or by sending it to the remote MCP you switch on in the app.
  5. The agent edits your source. You reload the page and check the result.

What the agent gets, and what the tool never does

The request carries

  • An anchor and a selector that still fit the element after the page re-renders
  • The styles that actually apply to it
  • The element's surroundings, its size and position in the viewport
  • The system the site runs on — WordPress, Shopify, Shoptet, Webflow or Wix, when the page makes it knowable
  • A crop of the element as an image — through the share sheet and in the zip; over MCP the agent downloads it from the address in the request
  • Optionally the page's speed — transfer and Web Vitals; a slow or shifting element goes out with an anchor, not as a bare number

What it never does

  • Never writes to your code and connects to no git
  • Never alters the page you are looking at — it only reads it
  • Calls no model; you pay for that at your own agent
  • Sends nothing on its own; the page content stays on your device
  • Neither hosts nor maintains anyone's website

The only way out leads through the remote MCP, and you are the one who switches it on. Only what you sent travels that way — the sentence, the anchor and the crop you attached — nothing else from the page. The list sits with us for a week after the last request and then disappears; turning the switch off deletes it at once. We don't read it and we learn nothing from it. Privacy policy.

Connecting your agent

The clipboard, the zip and the share sheet work with no setup. If you want the requests to land at your agent directly, switch on sending in the app's Connections section and copy the MCP address from there — paste it once into your client (Claude Code, Cursor, VS Code, Windsurf, Zed, Cline) and the agent reads the requests and ticks them off itself. There is nothing to install and no account is created: the address carries the key to your list, and that is a secret, not a login.

The browser extension

For Chrome and the other Chromium browsers — Edge, Brave, Arc, Vivaldi. It isn't in the store yet, so it is loaded by hand from an unpacked folder. That takes a minute and needs no invitation.

Install it by hand

Download the zip, unpack it and point the browser at it. The folder has to stay where it is — the browser loads it from disk at every start.

Download the extension (.zip)
  1. Unpack the zip into a folder you will not delete or move.
  2. Open chrome://extensions — in Edge edge://extensions, in Brave brave://extensions.
  3. Turn on Developer mode with the switch at the top right.
  4. Click Load unpacked and pick the unpacked folder.
  5. Open your website and call up the palette with the toolbar icon or the ⌘⇧E (Ctrl+Shift+E) shortcut.

To update: download again, overwrite the folder's contents and hit Reload on the extension in chrome://extensions. At every start the browser asks whether to keep running an extension in developer mode — that comes with installing by hand and goes away once the extension is in the store.
